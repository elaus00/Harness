# SK하이닉스 해커톤용 Harness 요구사항과 설계안

현재 범위는 [파일 추출형 계획](2026-11-05-portable-exam.md)으로 대체됐다. 사용자는 clone 보관소에서 파일을 별도 작업 폴더로 꺼내 쓰며, Docker 구성·컴파일은 실제 과제의 지정 디렉터리에서 직접 수행한다. 아래 Docker·clone 즉시 실행 조건은 최초 요구 기록이며 현재 완료 기준이 아니다.

- 날짜: 2026-11-05 (Asia/Seoul)
- 상태: 요구사항 접수, 설계안 제안. 구현 및 시험 환경 검증 전.
- 대상: 이 Harness 저장소 전체를 clone하여 사용하는 웹 IDE의 가상 컴퓨터.
- 환경 확인: 사용자가 시험용 가상 컴퓨터에서 Docker·Compose를 사용할 수 있다고 답변했다. 웹 IDE 제품명과 접속 방식은 아직 미확인이다.
- 후속 기준: 사용자가 추가한 README 보호·3층 구조 기준의 충족 여부와 수정 제안은 [기준 점검](2026-11-05-hackathon-audit.md)에 기록했다. 아래 표는 최초 점검이며, 스킬 동봉과 설치 도구는 후속 작업에서 보완했다. 결정 문서 경로 제안은 후속 기준의 `docs/DECISION.md`를 따른다.

## 사용자 요구사항

1. SK하이닉스 해커톤에서 사용할 개발 하네스를 제공한다.
2. `git clone`으로 실행 코드와 AI 작업 환경을 함께 받는다.
3. Docker로 의존성 설치와 빌드가 가능해야 한다.
4. 백엔드와 DB, 프론트엔드와 백엔드는 이미 연결되어 있어야 한다.
5. `AGENTS.md`, `Decision.md`, 필요한 skills를 저장소에 포함한다.
6. 최종 시험은 로컬 PC가 아닌 웹 IDE의 가상 컴퓨터에서 수행한다.

## 현재 구성과 차이

| 항목 | 현재 확인한 사실 | 보완할 내용 |
| --- | --- | --- |
| Docker | 루트 Compose가 앱 Compose를 include하고 백엔드·프론트엔드를 빌드한다 | 깨끗한 clone과 시험용 Linux 환경에서 실행 확인 |
| 프론트엔드 → API | 상대 경로 `/api/v1` 요청을 Nginx가 backend로 프록시한다 | 웹 IDE가 제공하는 미리보기 주소에서 실제 인증·업무 흐름 확인 |
| API → DB | Python sqlite3를 사용하고 Docker named volume에 파일을 보존한다 | 실제 쓰기·읽기와 재시작 후 유지 검증. health API는 현재 DB 쿼리를 하지 않는다 |
| AI 지침 | 루트와 앱에 `AGENTS.md`가 있다 | 해커톤 목적·경로·검증 절차에 맞게 갱신 |
| 결정 기록 | `docs/decisions/0001-harness-layout.md`가 있다 | 사용자 요청 파일명 `Decision.md`를 진입점으로 제공하고 기존 결정 기록에 연결 |
| skills | Git 추적 대상은 회고 스킬 1개다 | 사용할 스킬과 참조 파일을 프로젝트 안에 포함하고 의존성·라이선스 확인 |
| 스킬 기록 | `skills-lock.json`은 개인 컴퓨터의 전역 설치 목록이다 | clone 배포본에 포함된 파일을 상대 경로·출처·버전·해시로 구분하여 기록 |
| 웹 IDE | 현재 공개 포트는 `127.0.0.1:8080`이고 허용 Origin은 로컬 주소다 | 미리보기 방식에 맞는 포트 바인딩, Origin, HTTPS 쿠키 설정 안내 및 검증 |

이번 점검은 코드·Git 추적 파일과 문서 확인이다. 기존 문서의 Docker 성공 기록은 과거 로컬 arm64 환경의 결과이며, 해커톤 웹 IDE에서 성공했다는 근거로 사용하지 않는다.

## 접근안 비교

| 안 | 장점 | 비용·전제 |
| --- | --- | --- |
| A. 기존 FastAPI + React + SQLite 유지 — 권장 | 기존 연결을 활용하고 서비스·설정 수를 줄인다 | DB는 별도 서버 컨테이너가 아닌 백엔드에서 사용하는 파일 DB다 |
| B. 별도 DB 서버 컨테이너 도입 | 팀 개발에서 서버형 DB를 사용할 수 있다 | 드라이버·스키마·준비 상태·인증 설정과 데이터 접근 코드 변경이 필요하다 |
| C. 특정 웹 IDE용 환경까지 고정 | 포트 전달과 개발 도구 설정을 해당 플랫폼에 맞출 수 있다 | 플랫폼 이름·권한·Docker 지원이 먼저 확인되어야 한다 |

DB 종류는 사용자가 지정하지 않았다. A안을 제안하며 별도 DB 서버가 요구되면 B안으로 설계를 조정한다. 웹 IDE 이름은 아직 확인되지 않았으므로 특정 플랫폼의 지원을 가정하지 않는다.

## 권장 설계

- 실행: 기존 루트 `docker compose up --build -d --wait` 진입점을 유지한다. 앱 실행에 호스트 Python·Node 설치나 별도 DB 계정 준비가 필요하지 않게 한다.
- 연결: 브라우저는 웹 IDE에서 전달한 웹 포트 하나로 접속한다. Nginx가 정적 프론트엔드와 API를 제공하고, 백엔드가 DB를 읽고 쓴다.
- 준비 상태: 프로세스 생존과 DB 사용 가능 여부를 구분한다. DB 준비 실패 시 정상 실행으로 판정하지 않고 원인을 로그와 검사 결과에서 확인할 수 있게 한다.
- 저장: DB는 Docker named volume으로 보존한다. 일반 종료와 데이터 삭제 명령을 실행 안내에서 구분한다.
- 웹 IDE 설정: 외부 미리보기 Origin과 포트 바인딩을 설정으로 전달한다. HTTPS 미리보기에서는 Secure 쿠키를 검증한다. Origin 검사를 무조건 허용하는 방식은 사용하지 않는다.
- AI 문서: 루트 `AGENTS.md`에서 목적·구조·실행·검증·결정 기록을 안내한다. 루트 `Decision.md`는 결정 기록의 진입점으로 두고 상세 기록은 `docs/decisions/`에 유지한다.
- skills: `.agents/skills/`에 선택한 스킬의 본문과 필요한 참조 파일을 실제 포함한다. 필수 작업 흐름이 저장소 밖의 스킬이나 개인 절대 경로에 의존하지 않도록 참조 관계를 확인한다. 포함 목록은 설계 확정 시 정한다.
- 인증·도구: Git 접근 권한, 웹 IDE의 AI 확장 로그인, 외부 MCP 인증은 파일 동봉과 구분한다. 비밀값을 저장소에 포함하지 않는다.

## 구현 후 완료 판정

- [ ] 별도 작업 디렉터리에 clone한 추적 파일만으로 Docker 빌드가 성공한다.
- [ ] Compose가 서비스 준비 상태를 확인하고 실패 시 원인을 확인할 수 있다.
- [ ] 웹 IDE의 실제 미리보기 주소로 화면과 API에 접속한다.
- [ ] 회원가입·로그인·업무 생성·조회·수정이 화면에서 성공한다.
- [ ] 컨테이너 재생성 후에도 같은 볼륨에서 계정과 업무가 유지된다.
- [ ] 잘못된 DB 설정을 정상 준비 상태로 판정하지 않는다.
- [ ] `AGENTS.md`, `Decision.md`, 스킬 및 참조 파일이 clone 결과에 실제 존재한다.
- [ ] 시험에 사용하는 AI 도구에서 프로젝트 지침과 스킬 인식을 확인한다.
- [ ] 개인 컴퓨터의 전역 스킬·절대 경로 없이 필수 작업 절차를 수행한다.
- [ ] 실행 안내에 웹 IDE 포트 열기, 환경 설정, 검사, 종료·재시작 방법을 기록한다.

## 남은 확인과 다음 작업

Docker·Compose 사용 가능 여부는 사용자 답변으로 확인했다. 특정 웹 IDE 제품에 종속되지 않도록 미리보기 Origin과 포트 바인딩을 설정으로 제공하는 방향을 제안한다. 제품명은 구현을 시작하기 위한 필수 확인 사항으로 두지 않으며, 실제 시험 환경에서 포트 전달·HTTPS·인증 동작은 별도로 검증한다.

다음 순서: 권장 설계 확인 → 구현 계획 → 구성·문서·스킬 보완 → 깨끗한 clone 검증 → 실제 웹 IDE 검증.

애플리케이션 코드와 실행 구성은 변경하지 않았다. 후속 작업에서 Polars·humanizer-ko와 일괄 설치 기능을 추가했으며 실제 시험용 구조 전환은 아직 제안 상태다.
