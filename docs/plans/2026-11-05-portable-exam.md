# 파일 추출형 시험 Harness 보완 계획

- 상태: 구현·로컬 검증 완료. 사용자가 기존 보완안의 진행을 요청했고 clone 보관 폴더와 작업 폴더 분리, Docker 요구 제외로 범위를 수정했다.
- clone 저장소는 원본 보관소다. `templates/exam/`의 파일만 별도 작업 디렉터리로 선택 적용한다. 저장소 자체의 README·기존 대시보드·Docker 파일은 유지하되 반입본에는 포함하지 않는다.
- Docker 빌드·실행·설정 생성은 이번 완료 조건에서 제외한다. 사용자가 실제 과제의 지정 디렉터리에서 결정한다.

## 구현과 완료 기준

- [x] 시험용 짧은 AGENTS, INDEX·F/D/A·PRD·STATUS·작업 목록·빈 실행 양식과 핵심 프롬프트 제공.
- [x] 요구사항, 데이터 프로파일, 독립 검증기, 데이터 변형, 복귀, 제출 문서의 프로젝트 스킬 6개 추가. Polars·humanizer-ko·회고와 함께 일괄 설치.
- [x] 기존 파일 충돌·대소문자 충돌을 적용 전에 확인하는 exam 프로필 제공. README·AI_COLLABORATION·비밀값·로컬 산출물 제외. 기존 스킬은 폴더 전체 보존.
- [x] 최소 FastAPI와 정적 프론트엔드의 상대 경로 연결. 선택적 역할 인증, SQLite WAL·초기화·DB 준비 상태 확인, 환경변수 오류, 공통 오류 형식.
- [x] CSV 구문 검사와 데이터셋 버전·트랜잭션 적용, 작업 잠금·실패 복구·버전 추적·재계산 표시, 화면·복사·서버 저장 Export.
- [x] engine·validator는 별도 빈 인터페이스. 도메인 미구현은 성공으로 표시하지 않는다. 역할명·CSV 열·키·범위·가중치·Export 스키마는 현장에서 결정한다.
- [x] 원문 보존, 재적용, 잠금·원자성·권한·버전·검증 독립성·미구현 실패를 자동 검사하고 임시 추출본에서 실제 HTTP 흐름 확인.

## 실행 설계

문서만 필요하면 docs 프로필, 전체 연결부가 필요하면 exam 프로필, 스킬만 필요하면 기존 skills-only 옵션을 사용한다. 생성형 과제 기능은 설정으로 켠다. 기본 앱은 DB 상태와 로그인 연결만 제공하며 생성 알고리즘이나 유효성 판정을 내장하지 않는다. 초기 인증을 켜면 두 계정의 이름·비밀번호·역할을 환경설정에서 받는다. 서버가 허용하는 쓰기 역할도 설정으로 받는다.

데이터셋은 파일명과 원본 CSV 본문들의 묶음이며 스키마를 추론해 도메인 계약으로 확정하지 않는다. CSV 셀을 문자열로 보존하고, 일반 구문 검사와 현장 도메인 검증을 구분한다. 적용은 단일 DB 트랜잭션으로 새 버전과 활성 버전을 함께 갱신한다. 작업과 적용은 같은 SQLite 잠금 행을 사용해 여러 프로세스에서도 중복 실행을 막는다. 재시작 시 진행 중 작업을 임의로 취소하지 않으며, 별도 명시적 복구 명령은 실행 중 프로세스를 종료한 뒤 사용한다.

작업 결과는 생성 뒤 독립 validator로 판정하고, 검증하지 못했거나 위반이 있으면 정상 결과로 게시하지 않는다. 결과에는 데이터셋 버전·설정·보고서를 저장한다. 현재 데이터셋과 다른 결과는 재계산 필요로 표시하며 기본 Export를 막는다.

## 검증 기록

- 적용 도구: `python3 -m unittest discover -s tests -v` 14개 통과. 원문 바이트 보존, 재적용 보존, 스킬 참조·해시, 기존 내용·대소문자·심링크 충돌 시 무변경, 원본 해시 불일치 거부를 확인했다.
- 선택적 앱: `uv run --locked pytest -q` 28개 통과. WAL·DB 준비·필수 설정 오류, 역할·세션·초기 계정 동기화, CSV 문자열·결측·버전·적용 롤백, 생성 잠금·실패·재시작 복구, stale Export 차단, 독립 검증기 미구현·경계 검사를 확인했다.
- `ruff check`, 정적 검증기 의존성 검사, JS 구문 검사와 신규 스킬 6개의 quick_validate를 통과했다.
- 임시 별도 작업 폴더에 exam 프로필을 적용하고 해당 폴더에서 `uv sync --locked --python 3.12` 후 자체 가상환경으로 Uvicorn을 실행했다. clone 보관소의 Python 모듈 경로를 사용하지 않았다.
- 실제 Chromium 브라우저에서 DB 상태·로그인·CSV 구문 확인·버전 적용·빈 생성기의 501·실패 작업 표시·로그아웃·읽기 역할의 비활성 버튼 및 직접 요청 403을 확인했다. 모바일 화면과 브라우저 실행 오류 없음도 확인했다.
- 추출본의 README 원문과 저장된 CSV 내용이 보존됐음을 확인했다. 성공 결과·Export 검증은 명시된 테스트 전용 생성기·검증기 스텁으로 수행했으며 실제 도메인 구현은 없다.
- 임시 서버·작업 폴더는 정리했다. 동봉 범위는 9개 스킬과 40개 시험 파일이며 `.venv`·원문·Docker·런타임 DB는 제외된다.
- 공식 시험 환경·실제 AI 호스트의 스킬 인식·3시간 리허설·주최 측 반입 규정 확인은 수행하지 않았다. Docker는 사용자 요청으로 이번 검증 범위가 아니다. 이번 구현의 남은 로컬 작업은 없다.
