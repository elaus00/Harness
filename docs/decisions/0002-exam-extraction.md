# 0002: clone 보관소와 응시 작업 디렉터리를 분리

- 날짜: 2026-11-05
- 상태: 채택
- 근거: 사용자가 clone한 폴더를 별도 보관하고 파일을 꺼내 쓰며 Docker 컴파일은 지정 디렉터리에서 직접 수행하겠다고 명시하고 나머지 보완 진행을 요청했다.

## 결정

`templates/exam/`에 문제와 무관한 문서·최소 앱·빈 엔진 계약을 모은다. 스킬은 `.agents/skills/`의 동봉본을 사용한다. 적용 도구는 docs·exam·skills-only를 선택하고 원본 해시와 기존 파일 충돌을 쓰기 전에 확인한다. 응시 README·AI_COLLABORATION·Docker 파일은 추출하지 않는다. 기존 관리 저장소의 README·대시보드·Docker 예제는 유지한다.

시험용 문서는 대문자 INDEX·DECISION·STATUS·TASKS를 기준으로 하고 결정은 F/D/A ID로 구분한다. 개인 워크플로우 문서는 기존 경로를 유지한다. 둘을 자동 병합하거나 대소문자가 다른 문서를 중복 생성하지 않는다.

인증·생성형 과제 흐름은 선택 기능으로 둔다. 역할명·쓰기 권한·CSV 도메인 계약·계획 스키마·Export 컬럼과 알고리즘은 현장에서 결정한다. engine·validator는 빈 함수이며 미구현을 성공으로 표시하지 않는다. Docker 성공과 실제 시험장·3시간 리허설은 이번 구현 완료 주장에 포함하지 않는다.

## 검증 기준

추출 시 원문 보존·충돌 시 무변경, 문서·스킬의 자기완결성, DB 준비 상태·권한·원자성·잠금·버전 추적·실패 처리, 실제 추출본의 HTTP·화면 동작을 확인한다. 상세 결과는 파일 추출형 계획과 status에서 관리한다.
