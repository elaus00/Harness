# 독립 검증기

입력은 현장 README, 확정 입출력 계약(있다면 EXPORT_SCHEMA), 원본 데이터다. 생성기 구현·헬퍼·생성기의 판정값을 정답 근거로 쓰지 않는다. 별도 세션이 실제로 있을 때만 사용했다고 기록한다.

명시 제약을 REQ ID와 검사 ID로 연결한다. 모호한 계약은 질문·A ID로 남긴다. validator/에 데이터셋과 계획을 받아 보고서를 반환하는 검증을 작성한다. engine/ 및 앱의 생성 로직을 직접·간접·동적으로 import하지 않는다. 공통 데이터 형식·계약만 공유한다.

오류는 파일·행·열·이유와 규칙 ID를 담는다. 모르는 위치는 null이며 입력 오류·도메인 위반·미구현을 구분한다. 정상·경계·실패·복합 예시를 만들고 생성기의 출력만으로 기대값을 만들지 않는다.

tests/에서 독립 실행과 금지 의존성을 확인하고 동적 import·간접 헬퍼는 코드도 검토한다. 미구현·미실행은 위반 0건이 아니다. 생성기 오류를 맞추려고 제약을 완화하지 않는다. 계약은 DECISION, 구현·검사 결과는 TASKS·STATUS에 기록한다.
